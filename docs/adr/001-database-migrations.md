# ADR-001: Управление миграциями базы данных

**Статус:** Принято  
**Дата:** 2026-11-07

## Контекст

Приложению AI Product Card Generator необходим механизм управления изменениями схемы PostgreSQL.

Миграции должны выполняться в установленном порядке, фиксировать применённые версии и не запускаться повторно при последующих вызовах.

## Решение

Использовать собственный Python-раннер миграций `scripts/migrate.py` и SQL-файлы в каталоге `db/migrations/`.

Сведения о применённых миграциях хранить в таблице `schema_migrations`.

Для работы с PostgreSQL использовать библиотеку `psycopg`.

На текущем этапе не использовать Alembic.

## Обоснование

- Схема базы данных пока небольшая.
- SQL позволяет явно управлять расширением `pgvector` и объектами PostgreSQL.
- Собственный раннер помогает изучить механизм версионирования схемы.
- Не требуется дополнительная зависимость для управления миграциями.

## Последствия

**Преимущества:**
- Прозрачные SQL-миграции.
- Контроль порядка применения.
- Повторный запуск пропускает уже применённые версии.

**Ограничения:**
- Необходимо самостоятельно поддерживать раннер.
- Автоматический откат миграций не предусмотрен.
- При усложнении схемы может потребоваться переход на специализированный инструмент, например Alembic.
